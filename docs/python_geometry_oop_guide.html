2. 从“点线基础”到“曲面实体”的两步学习法

📍 第一步：回顾前序知识 · 0D 空间点与 1D 线性骨架
前几讲的核心任务是建立空间坐标基准与梁轴线。只有长度与尺寸，没有厚度与受力体积。
Point3D & Vector3D src/point3d.py

空间角点与位移荷载向量：给三维空间点赋予计算能力。两点相减直接得到跨度矢量 span = p_end - p_start，彻底告别零散的数组混乱。

✔ 运算符重载：符合土木力学公式书写直觉
Curve (基类) → Line3D src/line3d.py

轴线与钢筋路径：父类 Curve 强制规定了参数方程 point_at(t)，并承包了采样逻辑；子类 Line3D 仅需实现起点与终点间的线性插值。

✔ 初步体会：父类写通用管线，子类写具体插值
GeometryData src/_base.py

整个几何系统的法律规范：强制所有几何对象都有统一的 name 和 to_pyvista() 接口。凡是想要被屏幕渲染的物体，必须遵守此规则。

✔ 建立工业软件的统一接口规范 (契约化编程)
🌊 第二步：今日拓展进阶 · 2D 曲面与 3D 实体的三大工业范式
今天我们将几何维度升至 2 维连续曲面与 3 维闭合实体。深入剖析工业界三大截然不同的构造型态：

范式一：连续参数曲面 Parametric Surface

  • 土木应用：大跨索网屋顶（体育馆）、异形幕墙表皮 (扎哈风格)、连续箱梁放样。
  • 底层代码：ParametricSurfaceData（父类）划分 $(u, v)$ 参数网格；HyperbolicParaboloid（马鞍面子类）负责解析求值。
  • 最大优点：几百字节解析方程定义庞大结构，法向量光滑连续。
# src/hyperbolic_paraboloid.py class HyperbolicParaboloid(ParametricSurfaceData): def evaluate(self, u, v): # 子类仅写 3 行核心物理方程！ z = self.c * ((u/self.a)**2 - (v/self.b)**2) return Point3D(u, v, z)

范式二：边界表示实体 B-Rep Solid

  • 土木应用：Revit/Tekla 工业级 BIM 构件、框架柱、桥墩实心造型与布尔差集开窗开洞。
  • 底层代码：BrepData 维护 vertices(点)、edges(边)、faces(闭合面环)。
  • 拓扑守恒：服从欧拉-庞加莱公式 $V - E + F - R = 2(S - G)$，绝对保证体封闭不漏水。
# src/factories.py: create_cube_brep # 严格解耦：8个角点 + 12条边 + 6个闭合面 # 8 - 12 + 6 = 2 (拓扑完美闭合) brep = create_cube_brep(w, d, h)

范式三：离散多边形网格 Polygon Mesh

  • 土木应用：ANSYS / ABAQUS 结构有限元剖分 (FEA)、3D 激光扫描逆向点云重建、GPU 实时渲染。
  • 底层代码：MeshData 彻底抛弃“边”概念，只有顶点池 + 面片顶点索引表 (Index Buffer)。
  • 最大优点：专为显卡硬件光栅化着色打造，处理千万级面片依然流畅。
# src/factories.py: create_pyramid_mesh # 扁平结构：5个顶点 + 5个三角/四边面片索引 mesh = create_pyramid_mesh(w, d, h)

3. 面向对象 SOLID 五大设计原则（土木工程实战图解）

SOLID 是全球软件工业的五大黄金法则。在我们的 src/ 几何库中，处处都是 SOLID 原则的生动体现。结合土木设计与施工类比，一次性彻底搞懂：

S
单一职责原则
Single Responsibility
💡 土木类比：
梁只管承重，塔吊只管垂直吊装。构件与施工机具严格分工。
📁 源码落地：
BrepData 纯粹存储几何拓扑；RenderEngine 专门负责打光与三维视口。数据与显示解耦，更换渲染引擎绝不破坏几何本身。
O
开闭原则
Open-Closed
💡 土木类比：
大楼加装新型幕墙，无需砸毁核心筒剪力墙，预留标准转接件即可。
📁 源码落地：
需要增加“圆柱面”时，只需新建子类继承 ParametricSurfaceData。核心基类 _base.py 和 RenderEngine 零修改！
L
里氏替换原则
Liskov Substitution
💡 土木类比：
标准预制叠合梁无缝替换现浇梁。只要支座接口与标高一致，结构永不坍塌。
📁 源码落地：
调度器接收父类 GeometryData，传入 Point3D、Line3D、BrepData 均可透明替换，to_pyvista() 永不报错。
I
接口隔离原则
Interface Segregation
💡 土木类比：
强电插座与自来水龙头分开布设，不要强迫一根水管同时具备通电功能。
📁 源码落地：
Point3D 只需要坐标；只有曲面才有 u_range, v_range。总基类 GeometryData 绝不把网格划分等臃肿接口强塞给点和线。
D
依赖倒置原则
Dependency Inversion
💡 土木类比：
监理依据国家规范（国标 GB）验收工程，而不是绑定特定水泥小作坊。
📁 源码落地：
高层渲染调度 RenderEngine 只依赖抽象规范 GeometryData，绝不直接硬编码依赖马鞍面或立方体具体底层细节。
总结要诀

4. 土木人编程避坑与设计心法

📌 三句话记住今天这套代码的精髓：
1. 找共性放父类：只要是参数曲面，都要划分 $(u, v)$ 步长并转为 VTK 网格，所以写在 ParametricSurfaceData 里；
2. 个性留给子类：马鞍面的公式是马鞍面的，球面的公式是球面的，子类只重写 evaluate(u, v) 这一个函数；
3. 接口对外统一：无论内部是曲面、B-Rep 实体还是网格，对渲染引擎都只暴露一个 to_pyvista()，这就是工业软件极度稳定优雅的秘密！
