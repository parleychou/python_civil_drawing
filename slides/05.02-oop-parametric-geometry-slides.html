朴素建模

各自为战的朴素图元类

在最基础的面向对象思想下，如果不做进一步的抽象，我们通常会为每种图形编写一个类，直接继承自几何根基类 GeometryData：

  • 独立的特征属性：直线段持有 start 和 end；整圆和圆弧持有圆心、半径及角度。
  • 硬编码渲染实现：每个类都必须手写并实现自己专属的 to_pyvista() 方法。
  • 重复的代数计算：为了在 3D 空间中定位，圆与圆弧必须在内部手动获取局部基矢并循环进行三角函数插值采样。
虽然这样能画出图形，但底层的生成行为高度冗余，且使得几何内核与渲染引擎严重耦合。
# 各自动手实现 to_pyvista (以圆和线为例)
@dataclass
class Line3D(GeometryData):
    start: Point3D
    end: Point3D

    def to_pyvista(self) -> pv.DataSet:
        return pv.Line(self.start.to_tuple(), self.end.to_tuple())

@dataclass
class Circle3D(GeometryData):
    plane: Plane3D
    radius: float = 1.0

    def to_pyvista(self) -> pv.DataSet:
        points = []
        u, v = self.plane.local_axes()
        for i in range(72):
            angle = 2.0 * math.pi * (i / 72)
            offset_u = u.scale(self.radius * math.cos(angle))
            offset_v = v.scale(self.radius * math.sin(angle))
            pt = self.plane.center + offset_u + offset_v
            points.append(pt.to_tuple())
        
        polyline = pv.PolyData(points)
        polyline.lines = [73, *range(72), 0]
        return polyline
架构痛点

痛点剖析：野蛮生长的库

对比 Circle3D 与 Arc3D 的实现代码，我们可以直观地看到以下架构硬伤：

  • 重复的采样逻辑：两个类都在内部通过循环获取局部坐标轴 u, v、计算 cos 和 sin 乘法、做相同的平移相加。
  • 重复的网格封装：它们都在各自的方法中调用 pv.PolyData 并手动配置拓扑索引（lines），如果未来引入 20 种新曲线，就需要复制 20 份相同的打包样板代码。
  • 修改极其脆弱：若未来决定将渲染引擎换成 Matplotlib，必须把每一个图元类的 to_pyvista 函数全部重写一遍。

核心架构思考

  • 这些几何对象，底层到底有没有共同的数学本质？
  • “在指定范围采样点”和“打包成折线网格”的行为，是否能够提取为父类的通用算法？
  • 如何将“几何的数学定义”与“渲染网格构建”彻底解耦？
数学物理统一

参数化：用进度参数 t 统一曲线

解决重复代码的突破口，在于引入图形学最核心的思想：参数化表达（Parametric Representation）。

  • 进度参数 t：引入一个独立的无量纲参数 t（区间限制在 [0, 1] 之间）。
  • 运动的轨迹：不要把几何体看作死板的线条，而是将其看作一个点随着“时间”（参数 t）在三维空间中运动扫掠出的轨迹：P(t) = (x(t), y(t), z(t))。
  • 统一的行为契约：任何曲线只要给定一个 t 在 [0, 1] 之间的进度，都应该返回对应的空间 3D 坐标。
轨道比喻：参数化就像是在空间中铺设铁路，参数 t 就是列车从起点（0%）到终点（100%）的行程进度。

三大常用参数化映射公式

1. 直线段参数方程：
P(t) = (1 - t) * P_start + t * P_end

2. 整圆参数方程：
P(t) = P_center + R·cos(2πt)·u + R·sin(2πt)·v

3. 圆弧参数方程：
θ(t) = θ_start + t·(θ_end - θ_start)
P(t) = P_center + R·cos(θ(t))·u + R·sin(θ(t))·v

模板方法模式

Curve 类：让曲线计算一劳永逸

通过参数化接口，我们在 curve.py 中建立曲线基类 Curve：

  • 抽象方法契约：定义抽象方法 point_at(t)，强迫子类只实现这一个数学公式。
  • 统一的等分采样：在父类中统一实现 sample_points(count)，它在参数域 [0, 1] 间生成 t 并循环调用 point_at(t)。
  • 统一的网格打包：在父类中统一实现 to_pyvista()，完全依赖 sample_points() 生成的顶点来组装网格。
模板方法模式：父类负责统筹通用的行为逻辑（采样、网格生成），具体的算法公式（point_at）留给子类去“填空”。
# geometry_primitives/curve.py (核心抽象)
class Curve(GeometryData, ABC):
    @abstractmethod
    def point_at(self, t: float) -> "Point3D":
        """子类必须重写该方法，定义 t ∈ [0, 1] 上的点坐标"""
        pass

    def sample_points(self, count: int) -> list["Point3D"]:
        # 统一的采样算法：依赖 point_at(t)
        t_values = np.linspace(0.0, 1.0, count)
        return [self.point_at(float(t)) for t in t_values]

    def to_pyvista(self) -> "pv.DataSet":
        # 统一的网格折线组装算法：完全与具体子类解耦
        points = self.sample_points(72)
        pts_tuples = [p.to_tuple() for p in points]
        polyline = pv.PolyData(pts_tuples)
        polyline.lines = [len(points), *range(len(points))]
        return polyline
重写与多态

重构派生类：只保留纯粹的数学

继承 Curve 之后，子类的代码变得极其干净：

  • 仅保留参数字段 and 公式：没有了点集拼接、没有了 PyVista 导入，子类只专注于描述自己纯粹的数学几何意义。
  • 定制默认采样数：直线段默认采样 count = 2；整圆默认采样 count = 72；圆弧默认采样 count = 32。
高内聚低耦合：任何渲染、采样逻辑的变化，只需在父类中修改一处，所有具体曲线自动继承更新。
# Line3D 仅仅需要重写 point_at
@dataclass
class Line3D(Curve):
    start: Point3D = field(default_factory=Point3D)
    end: Point3D = field(default_factory=lambda: Point3D(1, 0, 0))

    def point_at(self, t: float) -> Point3D:
        return self.start * (1.0 - t) + self.end * t

    def sample_points(self, count: int = 2) -> list[Point3D]:
        return super().sample_points(count)

# Circle3D 也只需专注于极坐标与空间平面的映射
@dataclass
class Circle3D(Curve):
    radius: float = 1.0
    plane: Plane3D = field(default_factory=Plane3D)

    def point_at(self, t: float) -> Point3D:
        angle = 2.0 * math.pi * t
        u, v = self.plane.local_axes()
        offset_u = u.scale(self.radius * math.cos(angle))
        offset_v = v.scale(self.radius * math.sin(angle))
        return self.plane.center + offset_u + offset_v
面向对象四大特性实践

运算符重载与多态渲染的威力

面向对象并非“画蛇添足”，它在土木几何计算和引擎架构设计中展现出强大的工程实力：

  • 魔法方法（运算符重载）：重写 Point3D 和 Vector3D 的 __add__、__sub__ 方法，使我们能用 v = p_end - p_start，p = p_start + v 等极具数学美感的方式直接编程。
  • 渲染多态性：渲染引擎无需写大量的 if-else 去判断几何体类型，仅通过统一接口 item.render(engine)，底层就会自动动态绑定并执行各子类的渲染逻辑。
# 1. 运算符重载让几何运算浑然天成
start = Point3D(0, 0, 0)
end = Point3D(3000, 4000, 0)
direction_vector = end - start   # 触发 __sub__，得到 Vector3D

# 2. 对具体类型“视而不见”的多态渲染循环
objects: list[GeometryData] = [
    CoordinateSystem3D(),
    Line3D(Point3D(0,0,0), Point3D(5,5,5)),
    Circle3D(radius=500),
    Arc3D(radius=2000, start_angle=0, end_angle=math.pi)
]

for item in objects:
    item.render(engine)          # 运行时动态多态分发
离散化 (Discretization)

离散化：折线逼近光滑曲线

屏幕和显卡（WebGL 或 VTK/PyVista）只认识基本的线段和三角形，世界上不存在能被屏幕直接画出来的“完美圆滑曲线”：

  • 采样折线：为了渲染参数化曲线，必须将参数 t 在 [0, 1] 之间划分为 N 个等分值，算出对应的三维点并用直线段连接为折线（Polyline）。
  • 精度与性能的权衡：N 太小会有明显的折线楞角（如圆看起来像正八边形），N 太大会极度浪费显存和计算性能。

离散化在土木工程中的影响

  • 工程算量：若以太低的精度多边形近似圆柱体，会导致计算出的混凝土体积偏小，造成算量误差。
  • 碰撞检测：在进行 BIM Clash 检查时，粗糙的折线离散化会导致接触面处产生轻微的几何碰撞产生轻微误报或漏报。
  • 出图规范：低精度采样会让 CAD 导出的弧线图纸呈现出不合规范的锯齿折角。

课堂作业：开发三次贝塞尔曲线

贝塞尔曲线 (Bézier Curve) 广泛用于大跨度桥梁拱线、立交桥线形和异形建筑边界的表达。

开发任务：请在 scripts/geometry_primitives/ 中创建一个新的模块 bezier3d.py。要求：

  • 继承结构：新建 BezierCurve3D 继承自基类 Curve。
  • 数据参数：存储 4 个控制点：p0, p1, p2, p3 (类型皆为 Point3D)。
  • 计算内核：重写 point_at(t) 方法，实现三次贝塞尔曲线方程（根据参数 t 混合 4 个控制点）：

    B(t) = (1-t)³ * P0 + 3*(1-t)² * t * P1 + 3*(1-t) * t² * P2 + t³ * P3

  • 验证渲染：在 05_render_geometry_scene.py 中实例化一条贝塞尔曲线，并在 3D 视口中进行渲染。
# 贝塞尔曲线模板参考
from dataclasses import dataclass
from geometry_primitives.curve import Curve
from geometry_primitives.point3d import Point3D

@dataclass
class BezierCurve3D(Curve):
    p0: Point3D
    p1: Point3D
    p2: Point3D
    p3: Point3D

    def point_at(self, t: float) -> Point3D:
        # 三次贝塞尔曲线的伯恩斯坦多项式基函数
        b0 = (1.0 - t) ** 3
        b1 = 3.0 * ((1.0 - t) ** 2) * t
        b2 = 3.0 * (1.0 - t) * (t ** 2)
        b3 = t ** 3
        
        # 矢量合成
        x = b0*self.p0.x + b1*self.p1.x + b2*self.p2.x + b3*self.p3.x
        y = b0*self.p0.y + b1*self.p1.y + b2*self.p2.y + b3*self.p3.y
        z = b0*self.p0.z + b1*self.p1.z + b2*self.p2.z + b3*self.p3.z
        return Point3D(x, y, z)

    def sample_points(self, count: int = 40) -> list[Point3D]:
        return super().sample_points(count)
本节小结

面向对象与参数化建模的核心收束

本课时深入剖析了面向对象设计与图形参数化背后的软件工程哲学与数学方法：

  • 软件架构：GeometryData 与 Curve 并非画图的线条，而是底层的计算协议。它们把三维空间位置的数学计算与渲染系统的细节进行了彻底的解耦。
  • 参数表达：计算机图形学以归一化的参数 t (0 到 1 之间) 作为媒介，将连续的几何方程转换为离散的点网格，这是现代 BIM 模型能在电脑屏幕上展现的终极奥秘。
掌握了这两者，你们就具备了像软件开发人员一样编写建筑设计逻辑的能力，而不再局限于做普通的图纸消费者。
